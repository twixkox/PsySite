# PsySite — сайт психолога на ASP.NET Core

Личный сайт специалиста: главная, «Обо мне», проекты, тексты, события, записи вебинаров,
запись на консультацию с оплатой, продажа платных материалов, подписка на рассылку и админка.

**Технологии:** .NET 10, ASP.NET Core MVC (Razor), Entity Framework Core; база — SQLite (по умолчанию), PostgreSQL или SQL Server.
Никаких тяжёлых фреймворков на фронте — обычные Razor-шаблоны, CSS и немного JavaScript.

---

## Запуск

Нужен **.NET 10 SDK**: https://dotnet.microsoft.com/download

**Visual Studio 2026** (или Rider, или VS Code с расширением C# Dev Kit): откройте `PsySite.csproj` и нажмите F5.

**Из командной строки:**

```bash
cd PsySite
dotnet run
```

Сайт откроется на https://localhost:5001. При первом запуске создаётся база `App_Data/site.db`
и заполняется примерами — их можно поменять или удалить в админке.

**Админка:** https://localhost:5001/admin — логин `admin`, пароль `admin123`
(только в режиме разработки, задан в `appsettings.Development.json`).

Чтобы начать с чистой базы, остановите сайт и удалите папку `App_Data`.

## Как работает запись на консультацию

1. В админке («Расписание») создаёте свободные окна: на период, по дням недели, в нужное время.
2. Клиент выбирает формат, время и заполняет форму.
3. Если формат платный и включена предоплата — клиент попадает на страницу оплаты.
   Время держится за ним 30 минут (`Site:UnpaidBookingHoldMinutes`), потом освобождается.
4. После оплаты (или сразу, если оплата не нужна) клиенту и вам приходят письма.
5. В админке («Записи») видно все записи; можно подтвердить, отметить проведённой или отменить
   (окно при отмене снова становится свободным).

Одно окно нельзя занять дважды: бронь делается одной атомарной операцией в базе.

## Оплата

Сейчас включена **тестовая оплата** (`"Payments": { "Provider": "Fake" }`): вместо банка
открывается страница с кнопкой «Оплатить (тест)», деньги не списываются. Весь путь
«запись → оплата → письмо» можно проверить без договора с банком.

Тестовая оплата работает **только в режиме разработки**. На боевом сайте (`Production`) она
выключена: иначе любой посетитель мог бы «оплатить» консультацию без денег. Пока там не подключена
настоящая платёжная система, покупатель увидит «Онлайн-оплата сейчас недоступна», а оплату
можно отметить вручную в админке. Для тестового сервера её можно включить настройкой
`Payments:AllowFakeInProduction = true`.

### Подключение ЮKassa

Готовый класс — `Services/Payments/YooKassaPaymentProvider.cs`.

1. Заключите договор с ЮKassa, возьмите в личном кабинете `shopId` и секретный ключ.
2. В настройках:
   ```json
   "Payments": {
     "Provider": "YooKassa",
     "YooKassa": { "ShopId": "123456", "SecretKey": "live_..." }
   }
   ```
   Секретный ключ лучше задать переменной окружения `Payments__YooKassa__SecretKey`.
3. В кабинете ЮKassa → «Интеграция» → «HTTP-уведомления» укажите
   `https://ваш-сайт/pay/webhook` и включите событие `payment.succeeded`.
4. **Чеки по 54-ФЗ.** Если продавец — ИП или ООО, ЮKassa нужно передавать данные для чека
   (поле `receipt`). Для самозанятых ЮKassa может сама отправлять чеки в «Мой налог».
   Уточните у владельца сайта и при необходимости добавьте `receipt` в `StartAsync`.

### Другая платёжная система

CloudPayments, Robokassa, Т-Банк и т.п. подключаются так же: напишите класс, реализующий
`IPaymentProvider` (три метода: создать платёж, проверить статус, разобрать уведомление),
и добавьте его выбор в `Program.cs` рядом с ЮKassa. Остальной код менять не нужно.

Заказ можно отметить оплаченным и вручную — в админке «Заказы» (если клиент перевёл деньги по реквизитам).

## Письма

Пока SMTP не настроен, письма не отправляются, а печатаются в консоль — удобно для проверки.
Для настоящей отправки заполните раздел `Smtp`, например для Яндекс Почты:

```json
"Smtp": {
  "Host": "smtp.yandex.ru", "Port": 587, "UseSsl": true,
  "User": "site@yandex.ru", "Password": "пароль приложения",
  "From": "site@yandex.ru", "FromName": "Имя Фамилия"
}
```

Для Яндекса нужен не обычный пароль, а «пароль приложения» из настроек аккаунта.
Уведомления о новых записях и оплатах приходят на `Site:ContactEmail`.

## База данных

По умолчанию — **SQLite**: файл `App_Data/site.db`, ничего ставить не нужно, база и таблицы
создаются при первом запуске. Для PostgreSQL или SQL Server поменяйте две настройки:

| База | `Database:Provider` | Пример `ConnectionStrings:Default` |
|---|---|---|
| SQLite | `Sqlite` | `Data Source=App_Data/site.db` |
| PostgreSQL | `PostgreSql` | `Host=localhost;Port=5432;Database=psysite;Username=psysite;Password=...` |
| SQL Server LocalDB | `SqlServer` | `Server=(localdb)\\MSSQLLocalDB;Database=PsySite;Trusted_Connection=True;TrustServerCertificate=True` |

В JSON обратный слэш пишется двойным: `(localdb)\\MSSQLLocalDB`.

Для PostgreSQL базу и пользователя создайте заранее (`CREATE USER psysite WITH PASSWORD '...';
CREATE DATABASE psysite OWNER psysite;`), таблицы сайт создаст сам. Если подключиться не удалось,
сайт останавливается и пишет строку `FTL` с подсказкой на русском, что проверить.

Таблицы создаются только в пустой базе и потом не меняются. Если после обновления сайта появилась
ошибка `no such column`, при разработке достаточно удалить `App_Data/site.db`; на боевом сайте
с данными так делать нельзя — нужны миграции EF Core.

Код подключения — `Data/DatabaseSetup.cs`.

## Безопасность

**Что уже сделано в коде:**

| Угроза | Защита |
|---|---|
| Подделка форм с чужого сайта (CSRF) | Каждая форма подписана скрытым токеном, без него запрос отклоняется |
| Внедрение скриптов (XSS) | Всё, что вводят посетители, экранируется; политика CSP запрещает чужие скрипты |
| SQL-инъекции | Запросы к базе только через Entity Framework с параметрами |
| Подбор пароля админки | 10 попыток за 15 минут с одного адреса; на боевом сайте пароль не короче 10 символов |
| Украденный пароль | После смены пароля все старые входы в админку сразу перестают работать |
| Оплата без денег | Тестовая оплата работает только при разработке; уведомлениям платёжной системы не верим на слово — статус платежа перепроверяется запросом в ЮKassa |
| Подмена цены | Сумма всегда берётся из базы, а не из формы |
| Загрузка вредоносного файла | Проверяется содержимое файла (настоящая ли это картинка), имя файла случайное |
| Встраивание сайта в чужую страницу | Заголовки `X-Frame-Options` и `frame-ancestors` |
| Спам-боты | Скрытое поле-ловушка и ограничение частоты отправки форм |
| Доступ к чужим файлам через журнал | Скачать можно только файлы из папки логов |
| Утечка персональных данных через логи | Почты маскируются, имена, телефоны и заметки не пишутся |

Заголовки безопасности настраиваются в `Security/SecurityHeaders.cs`. Если добавите на сайт внешний
сервис (счётчик Яндекс Метрики, виджет, чат), его адрес нужно вписать в политику — иначе браузер его заблокирует.

**Что нужно сделать при выкладке на сервер — это уже не код, а настройка:**

1. **HTTPS обязателен.** Сертификат бесплатно через certbot (Let's Encrypt). Без HTTPS пароль
   админки и данные клиентов передаются открытым текстом.
2. **Надёжный пароль админки** через переменную окружения `Admin__Password`, не в файле.
   Не короче 10 символов, лучше 16+. Сайт не пустит в админку с коротким паролем.
3. **Не запускайте боевой сайт в режиме `Development`** — там пароль `admin123` и подробные
   страницы ошибок. Должно быть `ASPNETCORE_ENVIRONMENT=Production`.
4. **Подключите настоящую оплату** до того, как открывать платную запись. Пока стоит `Fake`,
   оплатить онлайн нельзя (в журнале ошибок будет напоминание).
5. **`AllowedHosts`** в `appsettings.json` — замените `*` на ваш домен (`example.ru;www.example.ru`).
6. **Права на файлы:** сайт работает от отдельного пользователя (`www-data`), папка `App_Data`
   доступна только ему: `chmod 700 /var/www/psysite/App_Data`.
7. **Закройте лишние порты** на сервере: наружу только 22 (SSH), 80 и 443. Сайт слушает
   `127.0.0.1:5000`, к нему ходит только nginx. Вход по SSH — по ключу, а не по паролю.
8. **Обновления:** `apt upgrade` для системы и раз в пару месяцев `dotnet list package --vulnerable`
   для проекта (проверка библиотек на известные уязвимости; сейчас уязвимых нет).
9. **Резервные копии** `App_Data` и `wwwroot/uploads` — на другой сервер или в облако, не на тот же диск.

**Что пока не закрыто и стоит иметь в виду:**

- Бесплатный формат консультации без предоплаты может занять бот или недобросовестный человек,
  записавшись на все окна с разных адресов. Защита от частых отправок это замедляет, но не исключает.
  Если начнётся — поможет подтверждение записи по ссылке из письма или ручное подтверждение.
- Админ один, вход только по паролю. Для сайта одного специалиста это нормально; если админов
  станет несколько или нужна двухфакторная защита — это отдельная доработка.
- Тексты страниц в админке можно редактировать как HTML. Это нужно для оформления, но значит,
  что админке надо доверять: доступ к ней — только у владельца сайта.
- Юридическая часть (политика конфиденциальности, согласие на обработку данных, уведомление
  Роскомнадзора об обработке персональных данных) — заготовки страниц есть, тексты должен
  подготовить юрист или владелец сайта.

## Логи

Сайт ведёт журнал всего, что с ним происходит. Смотреть его удобнее всего в админке:
**«Журнал»** (`/admin/logs`) — с поиском, фильтрами «только ошибки» и «действия в админке»
и кнопкой «Скачать файл». Если за сегодня были ошибки, на «Сводке» появится красная плашка.

**Что записывается:**

- каждая открытая страница: адрес, код ответа, время ответа, IP (картинки и стили — нет);
- записи на консультации, отмены, заказы, оплаты и уведомления от платёжной системы;
- отправка писем и ошибки отправки (с причиной: неверный пароль, сервер недоступен и т.п.);
- вход в админку, неудачные попытки входа, выход;
- **все изменения в админке** — кто, что, с каким объектом и чем закончилось
  («admin — удалён материал №7 «Сказки о силе» → выполнено»), выгрузка подписчиков;
- срабатывание защиты от спама и ловушки для ботов;
- сбои сайта — с полным описанием ошибки; посетитель при этом видит аккуратную страницу «Что-то пошло не так»;
- запуск и остановка сайта (а если сайт не смог запуститься — причина в `startup-*.log`).

**Персональные данные в лог не пишутся полностью:** почта выглядит как `an***@example.com`,
имена и телефоны клиентов, тексты заметок и комментариев не записываются вовсе — только номера
записей и заказов. По номеру всегда можно найти полные данные в админке.

**Где лежат файлы:** `App_Data/logs`

| Файл | Что в нём | Хранится |
|---|---|---|
| `site-20261026.log` | всё подряд, один файл на день | 30 дней |
| `errors-20261026.log` | только предупреждения и ошибки | 90 дней |
| `startup-20261026.log` | ошибки при запуске (появляется, только если они были) | 10 файлов |

Старые файлы удаляются сами. Если файл за день вырос больше 50 МБ, начинается следующий
(`site-20261026_001.log`). Сроки и размер меняются в разделе `Logs` в `appsettings.json`.

**Подробность записи** задаётся в разделе `Serilog` → `MinimumLevel`. Уровни от подробного к важному:
`Debug` → `Information` → `Warning` → `Error` → `Fatal`. Например, чтобы видеть текст отправляемых
писем (удобно, пока не настроена почта), в `appsettings.Development.json` уже стоит `"PsySite": "Debug"`.
Значение `Fatal` для служебных разделов Microsoft означает «почти не писать»: их ошибки и так
попадают в журнал одной строкой с полным описанием, без дублей.

Код логирования: `Logging/LoggingSetup.cs` (куда и как пишется), `Logging/LogMask.cs` (маскирование),
`Areas/Admin/AdminAuditFilter.cs` (журнал действий в админке), `Logging/LogReader.cs` (страница «Журнал»).

## Настройки (appsettings.json)

| Ключ | Что это |
|---|---|
| `Site:Name`, `Site:Tagline` | Имя и подпись в шапке, на главной, в письмах |
| `Site:ContactEmail` | Куда присылать уведомления, адрес в подвале |
| `Site:BaseUrl` | Адрес сайта (для ссылок в письмах) |
| `Site:TimeZone` | Часовой пояс расписания, по умолчанию `Europe/Moscow` |
| `Site:BookingMinHoursAhead` | За сколько часов закрывается запись на окно |
| `Site:UnpaidBookingHoldMinutes` | Сколько минут ждать оплату |
| `Admin:Login`, `Admin:Password` | Вход в админку (на боевом сайте пароль не короче 10 символов) |
| `Payments:AllowFakeInProduction` | Разрешить тестовую оплату не в режиме разработки — только для тестового сервера! |

Любую настройку можно переопределить переменной окружения: двоеточие заменяется
на два подчёркивания, например `Admin__Password=...`. Пароли и ключи храните так,
а не в файле, который попадает в git.

## Публикация на сервер (Linux VPS)

1. На сервере установите .NET 10 Runtime (ASP.NET Core) и nginx.
2. Соберите сайт: `dotnet publish -c Release -o publish` и скопируйте папку `publish` на сервер,
   например в `/var/www/psysite`.
3. Создайте службу `/etc/systemd/system/psysite.service`:
   ```ini
   [Unit]
   Description=PsySite
   After=network.target

   [Service]
   WorkingDirectory=/var/www/psysite
   ExecStart=/usr/bin/dotnet /var/www/psysite/PsySite.dll --urls http://127.0.0.1:5000
   Restart=always
   User=www-data
   Environment=ASPNETCORE_ENVIRONMENT=Production
   Environment=Admin__Password=надёжный-пароль
   Environment=Site__BaseUrl=https://example.ru
   Environment=TZ=Europe/Moscow

   [Install]
   WantedBy=multi-user.target
   ```
   Затем `systemctl enable --now psysite`.
   Строка `TZ=Europe/Moscow` нужна, чтобы время в логах было московским (серверы обычно работают в UTC).
4. В nginx проксируйте домен на `http://127.0.0.1:5000` и получите сертификат через certbot.
5. Делайте резервную копию папки `App_Data` (там база и логи) и `wwwroot/uploads` (загруженные картинки).

## Что можно доработать дальше

- Перейти с `EnsureCreated` на миграции EF Core, когда структура базы начнёт меняться
  на «живом» сайте (`dotnet ef migrations add Initial`).
- Напоминание клиенту за день до консультации (фоновая задача + письмо).
- Отзывы, галерея, страница книги с покупкой.
- Интеграция с сервисом рассылок по API вместо выгрузки CSV.
